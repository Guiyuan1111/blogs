## 一、问题反馈（重点）：代码块语法高亮在保存时被服务端剥离

### 现象

1. **新发布的文章，代码块没有语法高亮**。即使在编辑器里用「插入/编辑代码示例」工具正常生成、内容里带有完整的高亮标签，保存后打开文章，代码仍是纯黑白文本。
2. **老文章一旦重新编辑保存，高亮也会永久丢失**。早期发布的文章（如空间 3614 的 35661《VMware那些事儿》）代码块是彩色的——其 HTML 中内嵌了 Prism 的 `<span class="token …">` 标签；这些文章只要再走一次当前版本的保存流程，颜色就会被剥掉。

### 复现步骤

1. 打开文章创建页，用编辑器的「插入/编辑代码示例」插入一段代码（如 bash/powershell）。
2. 保存发布，打开新文章：代码块为纯黑白文本。
3. 用浏览器开发者工具抓包可见：编辑器提交的内容中代码块结构为 `<pre class="language-bash"><span class="token …">…`（带高亮），而落库后重新拉取的正文里 `<span class="token…">` 已被剥除，仅剩 `<pre class="language-bash">纯文本</pre>`。
4. 对照：老文章 35661 的正文在库中保留 token 标签（彩色）；新建文章 46698 / 46699 同样结构的内容被剥（黑白）。据此判断剥离发生在**服务端入库净化环节**，而非编辑器。

### 影响面

- 所有新发布文章的代码块均无语法高亮，技术类文章可读性明显下降；
- 用户重新编辑任何早期文章都会不可逆地丢失已有高亮（建议在官方公告中提醒用户，或在问题修复前阻止老文重存）。

### 修复建议

入库净化改为**白名单机制**而非整体剥离：对 `pre[class*="language-"]` 内部的 `span` 标签保留 `class` 属性（值限定 `token`、`token.comment`、`token.keyword` 等 Prism 类名），仅过滤危险属性（on*、style 中的 url/expression 等）。这样既保留高亮，又维持 XSS 防护。参考：Prism 官方输出的标签集合是有限闭集，白名单易维护。

## 二、自动化发布路径实测（如实披露，供平台安全参考）

本次测试仅在本人的账号与空间（3614）内进行，全程模拟真人浏览器操作，未绕过任何登录/鉴权。路径如下，供您了解当前接口在自动化面前的暴露程度：

1. 登录后，创建页为 `/spaces/{空间id}/resources/new?type=online`，正文编辑器为 TinyMCE 5.9.2（Vue 包装）。
2. 前端通过 Vue 组件数据模型（`form.content`）收集正文，编辑器的富文本状态与该模型之间存在同步缺口（直接 setContent 不会同步）——这也是可被脚本利用的点。
3. 最终保存请求为：
   `POST https://api.learnerhub.net/v1/products/{空间id}/pull_quests`
   body 结构：`{"pl_action":"create|update","product_file_id":<资源id>,"title":"…","pull_quest_items":[{"class_type":"ProductSnippet","title":"…","content":"<正文HTML>", …}]}`
4. 测试中未遇到验证码、频率限制或内容重复校验。

**建议**（供参考，非质疑）：对 `pull_quests` 这类写接口增加频率限制、同内容重复提交检测，或对高频自动化提交加入人机校验，可提高垃圾内容防护。
