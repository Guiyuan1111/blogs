# 博客发布工作流（Guiyuan1111/blogs）

本仓库是机主的个人技术折腾博客：**GitHub 仓库 [Guiyuan1111/blogs](https://github.com/Guiyuan1111/blogs)（公开）**，本地路径即本仓库根目录，分支 `main`，远程 `origin` 为 HTTPS（已用 gh 凭据代理配好认证，直接 `git push` 即可）。

## 发布一篇新文章的完整流程

### 1. 写作

- 稿子来源两种：用户直接提供成稿；或用户给主题/口述要点，由你按仓库既有风格撰写（参考 `posts/` 里已有文章）。
- 文件命名：`posts/【已解决】<产品/模块>报错<错误码或报错原文>-<关键症状>.md`（中文问题式，**不带日期前缀**）。
  - 文件名即检索标题：GitHub 渲染页的 `<title>` / `og:title` 就等于文件路径，所以文件名必须含真实报错码与症状关键词，写"问题"不写"故事"。
  - 文件名禁用字符 `\ / : * ? " < > |`：报错原文里的冒号用全角「：」或省略。
  - 旧规则 `posts/YYYY-MM-DD-<ascii-slug>.md` 已废弃（2026-09 由机主确认切换）；日期记在 README 目录表与文内。
- 文风要求（技术文档风，中文）：
  - **标题写"问题"不写"故事"**：`【已解决】<产品/模块>报错<报错原文>（<错误码> · <根因>）`
  - 居中头部 `<div align="center">`：`# 标题` + 一句话副标题 + 一行「关键词」（罗列同义报错串、错误码与工具名）+ shields.io 徽章（徽章要带真实数字/结论，不用空泛词）
  - 正文骨架（技术文档式）：0 摘要表（结论先行）/ 1 环境基线 / 故障模型或指纹 / 诊断步骤（命令可复制，含判读规则）/ 根因 / 修复选型与执行 / 验证表（前后对比）/ 局限与未验证项 / 命令速查 / 参考；叙事化的"概述 / 折腾记录 / 心得"不再使用
  - 使用 GitHub 提示块：`> [!NOTE]`、`> [!WARNING]`、`> [!IMPORTANT]`
  - 语气：真实、技术准确、不装；失败的尝试也要记录（每个失败排除一类假设）

### 2. 红线检查（每篇必过）

- **🔴 第一红线（优先级高于一切）：隐私与联系方式保护**。推送到 GitHub 的任何内容不得出现：邮箱、QQ/微信等联系方式、手机号、真实姓名、硬件序列号、账户 SID、含用户名的本机路径（`D:\Guiyuan1111\...` 必须写成 `D:\<本地路径>\...`）、内网 IP。git 提交邮箱必须保持 GitHub noreply 格式，**严禁**改成真实邮箱。
- **推送前强制隐私扫描——两条命令零输出才允许 `git push`**：
  ```bash
  grep -rinE "@qq\.com|@163\.com|@gmail\.com|@foxmail\.com|1[3-9][0-9]{9}|S-1-5-21|192\.168\.|序列号|serial" .
  grep -rin "Guiyuan1111" --include="*.md" . | grep -v "github.com/Guiyuan1111" | grep -v "Guiyuan1111/blogs"
  ```
  （注意：扫描规则文件本身不得包含机主的真实联系方式字面值，否则规则文件推送即泄密。已知机主的 QQ 号请凭会话记忆排查，不要写进任何文件。）**命中判读**：规则文件自身的规则描述行（含扫描模式与"不得出现…"字样）属于自指豁免；其余任何命中都必须先消除再推送。
- **AI 声明**：文末必须有 AI 生成声明（AI 辅助生成、ZCode/GLM 模型、操作为真实执行记录、关键决策经机主确认、仅供技术参考不构成保证）。
- **事实**：错误码、计数、时间线等必须来自真实执行输出，不得虚构；未经用户确认的决策不要写成已确认。

### 3. 更新目录表

编辑 `README.md` 的「📚 文章目录」表，在最上方插入新行：`| 日期 | [标题](posts/<文件名>) | 一句话简介 |`。同时视情况更新 README 顶部的"文章数"徽章数字。

### 4. 提交推送

```bash
cd /d/Guiyuan1111/blogs
git add -A
git commit -m "docs: <中文标题>"
git push
```

- 推送失败排查顺序：`gh auth status`（应显示 Logged in to github.com account Guiyuan1111）→ `gh auth setup-git`（重配 HTTPS 凭据）→ 再推。**不要**把 remote 改回 SSH。
- 推送成功后，把仓库链接和文章直达链接（`https://github.com/Guiyuan1111/blogs/blob/main/posts/<文件名>`）回复给用户。

### 5. 修改已发布文章

直接编辑 `posts/` 里对应文件 → 提交推送（commit 信息用 `docs: 修正 <文章名> <改动摘要>`）。

## 其他约定

- 仓库语言：中文为主；文章文件名用中文问题式（见 §1 文件命名），不用 ASCII slug。
- 用户可能口述零散要点——帮你成稿时先给用户看结构再发布，或直接发布后附链接（按用户习惯，发过一次后就沿用其偏好）。
- 机主背景备忘：技术爱好者，喜欢轻量/精简系统与硬件折腾，Windows 折腾经验丰富；本仓库第一篇为精简版 Windows 11 修复实录（`0x80073712`，UUP 就地升级）。
